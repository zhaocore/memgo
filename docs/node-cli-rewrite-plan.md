## 目标布局与依赖

实际文件布局及新增命令步骤统一维护在 [开发文档](../cli/node/development.md)，避免重复目录清单。

命令层依赖用例；用例依赖窄接口；入口装配具体 backend、配置存储、终端与遥测。Backend 不反向依赖 Commander、全局状态或输出样式。简单查询可直接调用 Backend，不为一行转发新增用例层。

- 用函数组织流程；仅外部连接器保留确有必要的类，错误类型按 TypeScript 标准继承 Error。
- 计算函数不修改输入；文件写入、网络调用和遥测集中在明确副作用边界。用每次调用的显式上下文替代可变模块全局状态。
- 区分 CLI 参数、用例输入和协议 DTO；metadata 等开放 JSON 使用递归 JSON 类型，不伪造固定业务字段。外部数据先验证必需字段，再进入业务层；无关额外字段按合同处理。
- 函数参数显式传递，无默认参数。以独立函数表达不同流程；既有 CLI 布尔选项保留，不据此设计多模式内部函数。
- process.exit 集中在入口；可恢复资源在退出前清理。错误转换、stdout/stderr 分配按已记录合同执行。
- 网络重试只用于已判定安全的瞬时错误，并记录脱敏告警；不可盲目重试写请求。具体次数、超时、幂等依据和退出行为在第一阶段记录，耗尽返回最后一个明确错误。
- `telemetry-sender.cjs` 随集成模块单独评估构建和运行路径；不为统一扩展名直接破坏子进程启动或打包。

## 验证命令与回滚

每阶段 Node 代码改动执行，工作目录为 `cli/node/`：

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
node dist/index.js --help
node dist/index.js --version
pnpm pack
```

仓库要求的完整单元测试执行 `go test ./...`；如涉及 Go 或共享构建流程，再执行 `go vet ./...`、`go build ./...`、`golangci-lint run`。服务端合同如受影响，必须另跑黑盒契约测试；破坏性清理测试 volume 前先确认数据可丢弃。Node 本地 HTTP 集成不能代替服务端契约验收。

按阶段审阅差异，记录兼容性和工具链变化。失败时只撤回当前阶段自己的改动，依据 P0 起点和保留的差异恢复，不执行全仓 reset、不覆盖用户文件。若未来另行发布后需回滚，恢复上一可用包版本；本计划不迁移配置、不改数据库，因此无需数据回滚。
